# گزارش کامل پروژه «مدیریت اتاق مشترک»

گزارش مرحله‌به‌مرحله‌ی طراحی و ساخت، روش راه‌اندازی (لوکال و آنلاین) و روش
استفاده‌ی روزانه برای اعضا و مدیر. برای معرفی کوتاه و جدول API به
[README.md](../README.md) نگاه کنید.

## ۱. شناسنامه‌ی پروژه

| مورد | مقدار |
| --- | --- |
| هدف | مدیریت کارهای مشترک یک اتاق ۸ نفره‌ی خوابگاه |
| زبان رابط | کاملاً فارسی، راست‌چین، تاریخ شمسی همه‌جا |
| فرانت‌اند | React 19 + Vite 7 + TypeScript + Tailwind CSS v4 + کامپوننت‌های VibeFarsi + vite-plugin-pwa |
| بک‌اند | Django 5 + Django REST Framework + SQLite (بدون Redis/Celery/Postgres) |
| احراز هویت | Django Auth با توکن + دو نقش `admin` و `member` |
| دیتابیس | SQLite (`backend/db.sqlite3`) |
| وضعیت | کامل و عملیاتی؛ تست قوانین، تست API و بیلد PWA سبز |

## ۴. مدل‌ها و منطق دامنه

- `accounts.User`: نقش `admin/member`، نام نمایشی فارسی، حرف آواتار.
- `schedule.SiteSettings`: سطر تکی؛ روزهای جاروبرقی (پیش‌فرض دوشنبه/چهارشنبه/جمعه = `[2,4,6]`)، تعداد نفرات (پیش‌فرض ۲)، فعال/غیرفعال بودن هر سه کار.
- `schedule.WeeklySchedule`: یک برنامه برای هفته‌ای که شنبه شروع می‌شود (`week_start` یکتا).
- `schedule.Assignment`: تاریخ + روز هفته (شنبه=۰) + نوع کار + مسئول + مسئول اولیه + وضعیت (`pending/confirmed`). قید یکتای `(date, assigned_to)` یعنی هیچ‌کس دو کار در یک روز ندارد.
- `schedule.SubstitutionRequest`: درخواست جایگزینی با وضعیت، دلیل، تصمیم‌گیرنده و زمان تصمیم.
- `schedule.SubstitutionCredit`: دفتر اعتبار معکوس (بدهکار/طلبکار، مبدأ، تسویه‌کننده).
- `expenses.Expense` / `ExpenseShare` / `Payment`: آیتم با مبلغ کل (تومان)، سهم مساوی هر عضو (باقی‌مانده به نفرات اول)، ادعای پرداخت با ۴ رقم آخر کارت و تأیید/رد ادمین. بدون درگاه پرداخت.

### الگوریتم زمان‌بندی (خلاصه)

شنبه=۰ تا جمعه=۶. روزها از شلوغ‌ترین (جمعه با ۵ اسلات) پر می‌شوند:

1. نظافت: هر روز ۱ نفر؛ با ۷+ عضو فعال هیچ‌کس دو بار در یک هفته نظافت ندارد.
2. جاروبرقی: روزهای ادمین × تعداد نفرات ادمین.
3. آشپزی: پنجشنبه و جمعه، هر روز ۲ نفر.
4. قانون سخت: حداکثر یک تکلیف برای هر نفر در هر روز (محافظ جمعه).
5. امتیاز نرم: سابقه‌ی بلندمدت هر نوع کار، ۴ هفته‌ی اخیر، تکرار هفته‌ی قبل، هم‌روز هفته‌ی قبل، بار هفته‌ی جاری + چرخش قطعی برای تساوی امتیازها.

### جایگزینی و اعتبار معکوس

مسئول (یا ادمین) برای تکلیف تأییدنشده جایگزینِ آزاد آن روز می‌خواهد → ادمین
تأیید/رد می‌کند. با تأیید، `assigned_to` عوض و `original_assignee` حفظ می‌شود.
اگر جایگزین قبلاً به مسئول اولیه بدهکار بود، همان اعتبار **تسویه** می‌شود؛
وگرنه اعتبار باز جدید ثبت می‌شود (مسئول اولیه بدهکار، جایگزین طلبکار).
پیشنهاد نامزدها: اول بدهکاران، بعد کم‌کارترین‌ها.

## ۵. راه‌اندازی محلی (قدم‌به‌قدم)

### پیش‌نیازها

- Python 3.11+ و Node.js 20+ (تست‌شده با Python 3.11 و Node 24)
- بدون نیاز به Postgres/Redis/Docker

### ۵-۱. بک‌اند

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
.\.venv\Scripts\python manage.py migrate
.\.venv\Scripts\python manage.py seed_room --demo
.\.venv\Scripts\python manage.py runserver
```

- آدرس: `http://127.0.0.1:8000` — پنل جنگو: `http://127.0.0.1:8000/admin/`
- رمز همه‌ی حساب‌ها: `room1234`
- حساب‌ها: `admin` (سوپریوزر)، `ali` (هم‌اتاقی با نقش ادمین)، بقیه عضو‌اند
- `--demo` برنامه‌ی هفته‌ی جاری + یک هزینه‌ی نمونه + یک پرداخت در انتظار می‌سازد.

### ۵-۲. فرانت‌اند

```powershell
cd frontend
npm install
npm run dev
```

- آدرس: `http://localhost:5173` — درخواست‌های `/api` خودکار به جنگو پروکسی می‌شود.
- بیلد نهایی PWA: `npm run build` (خروجی در `frontend/dist/`) و پیش‌نمایش: `npm run preview`

### ۵-۳. اعتبارسنجی (هر سه باید سبز باشند)

```powershell
.\backend\.venv\Scripts\python backend/manage.py check
.\backend\.venv\Scripts\python backend/manage.py shell --command "from schedule import tests_rules"
.\backend\.venv\Scripts\python backend/manage.py shell --command "from schedule import tests_api"
cd frontend; npm run build
```

خروجی مورد انتظار: `ALL SCHEDULING RULES PASSED` ،`ALL API SMOKE TESTS PASSED` و
`PWA ... precache ... entries`.

## ۶. استقرار آنلاین (کم‌حجم)

### ۶-۱. بک‌اند (gunicorn + SQLite)

```powershell
$env:DJANGO_SECRET_KEY="کلید-طولانی-تصادفی"
$env:DJANGO_DEBUG="0"
$env:DJANGO_ALLOWED_HOSTS="api.example.com"
$env:FRONTEND_URLS="https://room.example.com"
pip install -r backend/requirements.txt
python backend/manage.py migrate
python backend/manage.py seed_room
python backend/manage.py collectstatic --noinput
gunicorn config.wsgi --chdir backend --bind 0.0.0.0:8000
```

### ۶-۲. فرانت‌اند (هاست استاتیک)

```powershell
cd frontend
$env:VITE_API_URL="https://api.example.com"
npm run build
```

پوشه‌ی `dist/` را روی هاست استاتیک بگذارید با fallback همه‌ی مسیرها به
`index.html` (برای React Router) و نصب PWA از همان‌جا انجام می‌شود.

## ۷. راهنمای استفاده‌ی روزانه

### ورود

با نام کاربری (مثل `reza`) و رمز (`room1234`) وارد شوید. منوهای
«تأییدها/ساخت برنامه/اعضا/تنظیمات/آمار» فقط برای مدیر دیده می‌شود.

### عضو: کارهای روزانه

1. **داشبورد** (`/`): «وظایف امروز من» را ببینید و «تأیید انجام» را بزنید.
   «بقیه‌ی وظایف این هفته»، «بدهی من»، «موارد در انتظار» و «امروز در اتاق» هم همین‌جاست.
2. **برنامه** (`/schedule`): هفته را با فلش‌ها عوض کنید؛ روز امروز بج دارد.
   برای واگذاری کار خودتان «جایگزین» را بزنید، دلیل بنویسید و یک نفر آزاد آن
   روز را انتخاب کنید (بدهکاران شما با بج «جبران اعتبار شما» اول‌اند).
3. **جایگزینی‌ها** (`/substitutions`): دفتر اعتبار و وضعیت درخواست‌هایتان.
4. **هزینه‌ها** (`/expenses`): سهم خودتان را ببینید؛ بعد از کارت‌به‌کارت، ۴
   رقم آخر کارت را ثبت کنید تا «در انتظار تأیید» شود. ثبت هزینه‌ی جدید برای
   همه آزاد است (نام + مبلغ + انتخاب اعضا).

### مدیر: چرخه‌ی هفتگی پیشنهادی

1. **شنبه**: «ساخت برنامه» (`/admin/schedule`) → هفته‌ی هدف را چک کنید
   (معادل شمسی نمایش داده می‌شود) → «ساخت برنامه». «بازسازی» فقط وقتی مجاز
   است که تکلیف تأییدشده نباشد.
2. **تنظیمات** (`/admin/settings`): روزهای جاروبرقی و تعداد نفرات را عوض کنید
   یا کاری را موقتاً غیرفعال کنید؛ «بازنشانی پیش‌فرض» دوشنبه/چهارشنبه/جمعه‌ی ۲ نفره است.
3. **تأییدها** (`/admin/approvals`): هر روز جایگزینی‌ها و پرداخت‌ها را تأیید/رد
   کنید (بج بالای منو تعداد صف را نشان می‌دهد).
4. **اعضا** (`/admin/members`): افزودن/ویرایش/فعال-غیرفعال/حذف هم‌اتاقی (حذف خودتان ممنوع).
5. **آمار** (`/admin/stats`): کار هر نفر به تفکیک نظافت/جارو/آشپزی، صف‌ها و
   تاریخچه‌ی هفته‌ها برای کنترل انصاف بلندمدت.

### حالت تاریک/روشن و نصب موبایل

دکمه‌ی خورشید/ماه در نوار بالا تم را عوض می‌کند و ذخیره می‌ماند. در موبایل از
منوی مرورگر «نصب / Add to Home Screen» را بزنید تا «اتاق من» مثل اپ نصب شود.

## ۸. عیب‌یابی سریع

| علامت | علت و راه‌حل |
| --- | --- |
| خطای `No module named 'django'` | محیط مجازی فعال نیست؛ از `backend\.venv\Scripts\python` استفاده کنید |
| فرانت `401` و پرش به لاگین | توکن پاک شده؛ دوباره وارد شوید |
| «برای این هفته قبلاً برنامه ساخته شده» | با «بازسازی» بسازید یا هفته‌ی بعد را انتخاب کنید |
| «برنامه تکالیف تأییدشده دارد» | هفته‌ای که کاری در آن تأیید شده قابل بازسازی نیست |
| «جایگزین در این روز تکلیف دیگری دارد» | قانون یک کار در روز؛ فرد آزاد دیگری انتخاب کنید |
| بیلد PWA آیکون ندارد | `frontend/public/icons/` باید هر سه PNG را داشته باشد و `npm run build` دوباره اجرا شود |

## ۹. محدودیت‌های آگاهانه

- پرداخت واقعی بانکی نیست (عمداً): فقط ثبت ۴ رقم آخر + تأیید انسانی مدیر.
- اعلان‌ها داخل برنامه‌اند (Toast + بج)؛ پوش‌سرور ندارد تا پروژه کوچک بماند.
- SQLite تک‌فایلی است؛ برای همین مقیاس (یک اتاق) کافی و نگهداری‌اش ساده است.
